# 一人公司产品筛选框架

## 文档信息

- 状态：当前有效
- 适用阶段：点子筛选、产品组合选择、0→1 优先级判断
- 核心模型：六维产品筛选 + 四类持续价值

## 六维评分表

每项先用 1–5 分评分，再写证据。没有证据的分数只能标为假设，不能当结论。

| 维度 | 核心问题 | 强证据 |
| --- | --- | --- |
| 真需求 | 用户是否正在付出代价？ | 展示当前流程、真实样例、已付费替代方案 |
| 重复触发 | 什么时候会再次回来？ | 真实工作流日志、项目周期、异常触发、续费 |
| 付费意愿 | 谁付钱，为什么现在付？ | 付款、采购单、预算、试点合同 |
| 信任 | 用户敢不敢交付关键任务？ | 生产接入、敏感数据、审计和责任要求 |
| 获客效率 | 如何找到相似客户？ | 可重复渠道、转介绍、定向外联转化 |
| 单位经济 | 一单是否越做越赚钱？ | 毛利、支持工时、CAC、LTV、回收周期 |

## 判断公式

```text
真需求 × 重复触发 × 付费意愿 × 信任 × 获客效率 × 单位经济
```

乘法比加法更接近现实：一个维度接近零，整体商业价值就会显著下降。高频但不付费，仍然不是好生意；高客单但获客成本和交付成本更高，也不是好生意。

## 四类持续价值

### Daily Habit

每天或高频打开，依靠低摩擦和即时反馈留存。需要强激活、内容或网络效应，不是个人创业者的默认优先方向。

### Monitoring Habit

用户不一定每天操作，但系统持续监控，异常、变化或周期报告触发回访。

典型场景：GEO、SEO、舆情、财务、安全、数据质量和合规监控。

### Workflow Habit

用户在项目、变更、审核或任务启动时进入系统，历史数据、模板、协作和配置形成投入沉淀。

典型场景：APQP/FMEA、投标、科研证据工作流和企业交付系统。

### High-Stakes Tool

使用频率低，但关键时刻失败成本高，客户愿意为可靠性、审计、判断和结果付高价。

典型场景：质量、审计、合规、安全和专业数据服务。

## 对常见产品的分析方法

### 质量类产品

不要定位为“AI 工具箱”，而应识别核心工作单位，例如一个 APQP/FMEA 项目。

判断重点：

- 新项目、工程变更和审核是否重复触发。
- PFD、PFMEA、CP 是否需要一致性检查。
- 历史模板、审计记录和协作是否形成不可替代性。
- 客户是否愿意为减少返工和审核风险付费。

### GEO 类产品

不要只卖排名看板，应形成：

```text
监控 -> 解释变化 -> 提出行动 -> 执行 -> 再验证
```

判断重点：

- AI 推荐变化是否持续发生。
- 客户是否能看见 ROI 或至少看见可执行的因果链。
- 产品是否提供优化行动，而不只是分数。
- 获客是否能通过目标品牌、代理商或内容教育完成。

### 学术类产品

不要默认高频使用等于高付费。必须找到完整的科研 JTBD，例如：

```text
研究问题 -> 检索 -> 筛选 -> 证据表 -> 综述 -> 引用管理
```

优先验证实验室、团队或机构付费，而不是只看学生个人使用量。

### 金融信息类产品

高频筛选和日活不能替代付费理由。需要回答：

- 用户为什么愿意为决策结果付费？
- 免费替代品为什么不够？
- 如何处理错误建议、责任和信任？
- 用户是购买信息、工具、策略还是结果？

没有支付证据前，不应继续用增加筛选器和资讯功能掩盖商业闭环缺失。

## 一人公司最优方向

优先寻找：

- 特定角色在高价值时刻必需的工具。
- 一个团队可以独立购买和使用的工作流。
- 可通过服务、定向外联、转介绍或专业内容获客的产品。
- 高信任、高客单价、低频但不可替代的产品。
- 能沉淀数据、配置、历史和结果的产品。

谨慎进入：

- 需要大众日活的消费产品。
- 需要巨额广告投放的市场。
- 需要网络效应才能成立的平台。
- 高频使用但免费替代品极多的工具。
- 需要客户老板推动长期组织变革的企业方案。

## 最小验证实验

对每个候选产品设计六个实验：

1. 真需求访谈：客户展示最近一次真实流程。
2. 触发实验：记录客户什么时候会回来，而不是问“会不会每天用”。
3. 付费实验：要求真实付款或采购承诺。
4. 信任实验：让客户把一项真实但低风险任务交给产品。
5. 获客实验：用一个可重复渠道找到 10 个目标客户。
6. 经济实验：记录交付、支持、API、数据和获客成本。

## 决策规则

- 高频但低付费：先停功能扩张，重新寻找付费买家或结果价值。
- 高付费但低频：围绕项目、监控、续费、历史和高风险价值设计产品。
- 高信任但难获客：缩小垂直领域，使用服务和定向销售获得首批客户。
- 易获客但低毛利：减少定制，标准化交付并计算支持成本。
- 高度依赖老板推动：要求客户提供 champion/预算/权限，否则缩小为团队工具。

## 最终判断

不要寻找“人人每天都用”的产品。对一人公司，更值得寻找的是：

> **特定的人在一个足够值钱的时刻，一定会使用，并且没有它会承担明确损失。**
