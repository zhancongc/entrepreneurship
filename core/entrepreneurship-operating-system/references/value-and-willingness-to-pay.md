# 商业价值与支付意愿

## 核心模型

一个需求是否值得创业者投入，不只看用户是否喜欢，而要同时看：

```text
商业价值
≈ 支付能力 × 需求刚性 × 价值可量化程度 × 可触达性
```

常见的两条成立路径：

### 1. 高预算客户的大客单

客户愿意为以下结果支付高价：

- 增加收入。
- 降低重大成本。
- 降低事故、合规或质量风险。
- 通过审核或满足客户要求。
- 节省高薪人员时间。
- 在关键截止日期前完成高价值交付。

这类产品不要求每天使用，但必须在关键时刻可靠，通常对应 High-Stakes Tool 或 Workflow Habit。

### 2. 低预算用户的高频刚需小额付费

单个用户支付金额低，但需求：

- 高频发生。
- 低决策成本。
- 价值立即兑现。
- 用户规模足够大。
- 获客和支持成本足够低。

这类产品依赖规模、留存、低摩擦支付和高效分发，通常不适合没有流量、内容或网络效应的一人创业者直接复制。

## 低商业价值组合

以下组合要谨慎：

```text
高预算客户 + 低价值小单
```

客户虽然付得起钱，但问题对业务影响小，只愿意给很低价格，销售和交付成本可能吃掉利润。

```text
低预算用户 + 低频非刚需
```

用户可能觉得产品有趣，但连低价都不愿意付。这类产品最容易出现“使用反馈很好，商业转化很差”。

## 对 B2B 的修正

不要用“富人/穷人”字面判断，而要判断：

- 谁是付费组织。
- 预算来自哪个成本中心。
- 问题造成的损失有多大。
- 预算所有者是否能拍板。
- 购买是否有明确截止时间或强制事件。
- 客户是否愿意提供数据、权限和内部 champion。

一个普通员工使用的产品，如果能帮助企业减少一次客户审核失败或重大返工，可能是高价值产品；一个高收入个人使用的产品，如果只提供轻微便利，也可能只有低支付意愿。

## 澹墨质量的启示

澹墨质量更接近“高预算客户的大客单”路径，而不是低价大众工具。

它不应该卖：

```text
18 个质量 AI 工具
```

而应该卖：

```text
降低返工成本
提高 APQP/FMEA 交付速度
减少 PFD/PFMEA/CP 不一致
降低客户审核失败风险
```

潜在付费者可能不是单个工程师，而是：

- 质量部门负责人。
- 项目负责人。
- 供应商质量负责人。
- 需要通过客户审核的制造企业。
- 需要按时交付 PPAP/APQP 文档的团队。

### 价格逻辑

如果一次返工、审核失败或项目延期会造成数万元甚至更高损失，那么几百到几千元的项目费用可能合理；但前提是价值能被客户理解并由内部 champion 推动。

### 关键风险

澹墨质量仍然有两个约束：

1. 需求低频，必须围绕项目、变更、审核和历史沉淀形成 Workflow Habit。
2. 企业行动依赖高，必须确认预算、内部 champion、权限和试点责任人。

因此它的首个实验不应是“有多少人注册”，而应是：

```text
一个真实制造企业
提供一个真实 APQP/FMEA 项目
-> 完成一次交付
-> 量化节省时间/返工/风险
-> 愿意再次购买或签订团队试点
```

## 澹墨学术的启示

澹墨学术更容易落入“高频使用、低支付意愿”组合。

用户可能每天：

- 搜论文。
- 总结论文。
- 翻译论文。
- 问 AI 问题。

但个人用户未必愿意持续付费，因为：

- 有 ChatGPT、Claude、NotebookLM、Zotero 等替代品。
- 学生和普通研究者预算有限。
- 单个功能的边际价值容易被通用 AI 覆盖。
- “有帮助”不等于“必须购买”。

### 应该寻找更高支付能力的买家

优先验证：

- 实验室。
- 研究团队。
- 高校课题组。
- 企业研发部门。
- 咨询和研究机构。
- 需要团队共享证据库和审计链的组织。

### 应该卖完整 JTBD

不要卖：

```text
AI 学术工具箱
```

而应验证：

```text
研究问题
-> 检索
-> 筛选
-> 证据表
-> 综述
-> 引用管理
-> 团队复用
```

如果只能卖论文总结、翻译或 PDF 问答，商业价值容易被通用 AI 压低。若能帮助团队减少研究重复、建立可审计证据链、提高基金/项目交付效率，才可能进入高预算组织的大客单路径。

## 决策实验

对任意产品，在开发前回答：

1. 这是高预算大客单，还是低预算高频小额？
2. 付费者和使用者是否不同？
3. 价值能否用收入、节省时间、降低风险或完成交付量化？
4. 用户当前是否已经为替代方案付钱？
5. 是否有明确截止时间、审核、事故或刚性任务？
6. 获客成本和支持成本是否低于可实现收入？
7. 如果用户不付费，最可能的具体原因是什么？

## 最终判断

```text
高预算客户 × 高价值结果 × 可量化损失
```

或：

```text
低预算用户 × 高频刚需 × 低获客/支持成本 × 足够规模
```

这两条路径都可能成立。对一人公司，优先选择第一条通常更现实，因为不需要先获得巨大流量；但必须确认客户内部有预算、champion 和执行能力。
